# 전자결재 양식 편집기 — 소스

`app_flutter/web/eap_*.js` 로 배포되는 양식 편집기의 **소스와 검증 도구**가 있는 곳입니다.

## 왜 이 폴더가 생겼나

기존 편집기(`app_flutter/web/eap_html_editor.js`, 3,144줄)는 **`document.execCommand`** 위에
직접 만든 것입니다. execCommand 는 2020년에 W3C 에서 폐기됐고 브라우저마다 동작이 달라,
글자 서식 관련 버그가 구조적으로 계속 생깁니다. 이를 **TipTap(ProseMirror)** 기반으로
교체하는 작업의 작업 공간입니다.

## 가장 중요한 것 — 안전망

ProseMirror 는 **스키마에 없는 내용을 경고 없이 버립니다.** 이식이 조금이라도 부족하면
기존 결재 서식의 일부가 소리 없이 사라집니다. 그래서 엔진을 건드리기 **전에** 안전망부터
만들었습니다.

```
npm install          # 최초 1회
npm run fixtures     # 기준 데이터 생성(레거시 편집기를 실제로 돌려서 뽑음)
npm test             # 왕복 검증
```

- `tools/make-fixtures.mjs` — 레거시 편집기를 **jsdom 에서 그대로 실행**해 위젯 28종의
  "저장본 HTML" 을 뽑습니다. 손으로 붙여넣지 않고 스크립트로 만드는 이유는, 레거시가
  바뀔 때마다 기준을 다시 만들 수 있어야 하기 때문입니다.
- `test/signature.mjs` — HTML 에서 **사라지면 안 되는 것**(위젯과 그 설정, 표 구조,
  글자, 문서 블록)만 뽑아 비교합니다. 공백·속성 순서 같은 겉모습 차이는 무시합니다.
  엔진을 바꾸면 겉모습은 반드시 달라지므로, 그것까지 비교하면 테스트가 무용지물이 됩니다.
- `test/roundtrip.test.mjs` — 고정 데이터 28종 + **운영에 실제로 저장된 서식**을 대상으로
  ① 왕복해도 더 이상 변하지 않는지(안정성) ② 내용이 그대로인지(보존성) 를 봅니다.

현재 기준선: **35건 전부 통과** (레거시 편집기 기준).
TipTap 엔진이 붙으면 같은 검사를 새 엔진에도 돌려 이 기준선을 지키는지 확인합니다.

## 배포

번들 결과물은 `app_flutter/web/vendor/` 에 **커밋**합니다.
따라서 서버나 Flutter 빌드에는 node/npm 이 필요 없습니다 — 지금까지의 배포 절차 그대로입니다.
편집기 소스를 고친 사람만 `npm run build` 를 돌려 번들을 갱신하면 됩니다.

## 저장 형식은 바꾸지 않는다

DB(`eap_form_config.content_html`)에 들어가는 HTML 형식은 **그대로 유지**합니다.
위젯은 `data-eap-type` / `data-eap-label` 같은 속성으로 표현되고, 이 형식은 채우기 화면
(`eap_form_fill.js`)·미리보기(`eap_preview.js`)·백엔드가 모두 공유합니다.
바꾸는 것은 **편집 엔진뿐**입니다.
